# Proofline

[操作工作台](https://miiduoa.github.io/labs/proofline/) · [核心邏輯](core.mjs) · [自動測試](core.test.mjs)

小型、可重現的 SHA-256 稽核紀錄實驗。主題不是「雜湊能不能算出來」，而是：**如果有人能連檢查點一起重寫，要靠什麼證明紀錄沒被刪過？**

## 如何測試

網站根目錄使用 Node.js 22 以上版本：

```sh
node --test labs/proofline/core.test.mjs
```

在操作頁上比較五個情境：原始紀錄、修改事件、交換順序、截斷尾端、重新計算整條鏈。

修改事件與交換順序會直接打破原本的序號或雜湊。截斷後如果同步重寫檔案內建的檢查點，內部驗證可以通過；只有與**另外保存**的原始檢查點比較，才能發現歷史紀錄縮短。完整重算雜湊也一樣。

## 格式與假設

- 固定事件欄位：`id`、`at`、`actor`、`action`、`target`、`note`。
- 事件時間是毫秒精度、以 Z 結尾的 UTC ISO 格式；最多 100 筆，每筆 ID 不得重複。
- 每筆雜湊使用 Web Crypto SHA-256，輸入為 UTF-8 編碼的 `JSON.stringify(["proofline.v1", seq, previousHash, normalizedEvent])`。欄位順序固定，第一筆 previousHash 是 64 個 0。
- 檢查點是 `{count, hash}`；**是否值得信任取決於它存放的位置與權限**，不是 JSON 檔名。
- 匯入的紀錄與檢查點會在目前瀏覽器處理，沒有上傳服務；下載時也分開保存兩份檔案。

## 限制

這是驗證模型，不是正式稽核服務。只有雜湊不等於數位簽章，也不能證明時間來源、操作者身分或事件原始內容真實。示範檢查點預設保存在當前頁面記憶體中，並非實際的外部不可竄改儲存。真正的產品需要授權控管、可靠的時間來源、獨立的錨定機制及保留政策。
